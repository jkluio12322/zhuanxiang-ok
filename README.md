# BlueCar STM32F103 循迹小车


> ⚠️ **本文档描述 2026-11-05 重写前的旧架构**（五模式、39 条串口命令、trackbin、位置环），
> 与当前代码不符，仅作历史参考。现行架构请看 [CLAUDE.md](CLAUDE.md) 和 [功能概览.md](功能概览.md)。

本工程基于 STM32F103ZET6 和 STM32 HAL，实现八路数字循迹、双轮速度闭环、
OLED 状态显示和 VOFA+ 遥测。

本文只记录**当前源码能够确认**的参数和控制思路。硬件参数以实测使用的
JGB37-520 12V、178 RPM、1:56 减速版本和 11 PPR 编码器为准。

## 3. 电机与编码器参数

| 参数 | 数值 |
| --- | --- |
| 减速比 | 1:56 |
| 空载转速 | 178 RPM |
| 额定转速 | 140 RPM |
| 额定转矩 | 6.5 kg·cm |
| 堵转电流 | 2.3 A |

输出轴每转计数：

```text
counts_per_output_revolution = 4 * 56 * 11 = 2464
```

50 ms 滑动测速窗的转速换算为：

```text
RPM = count * 1200 / 2464
RPM = count * 0.487012987
count = RPM * 2.053333
```

车轮半径为 `0.065 m`，轮胎周长约 `0.408407 m`。

## 4. 控制架构

代码按职责分层，依赖只能向下：

```
Display / Comm  ->  State  ->  Control / Motion  ->  Scheduler  ->  Hardware
```

| 目录 | 模块 |
| --- | --- |
| `Config/` | `config.h`（全部可调参数）、`types.h`、`board.h`（引脚别名） |
| `Scheduler/` | `sched`（中断分发、延后任务、ConfirmCounter） |
| `State/` | `state`（唯一可变状态）、`imu`（IMU963RA 采样） |
| `Motion/` | `motion`（编码器、50 ms 测速窗、电机输出）、`speed_loop`（5 ms 速度 PI） |
| `Control/` | `pid`、`track`（循迹）、`testmode`（开环测试） |
| `interaction/` | `serial`、`console`（命令行）、`cmd`（按键与命令队列）、`telemetry` |
| `interaction/` | `display` |

### 4.1 任务与执行位置

TIM5 提供 1 ms 时间戳；TIM6 每秒触发 1000 次，由 `sched.c` 分频。

| 周期 | 任务 | 执行位置 |
| --- | --- | --- |
| 10 ms | IMU963RA 采样（SPI2 阻塞读 12 字节） | 主循环（TIM6 置 DEFERRED_IMU） |
| 20 ms | 按键状态机 + 按键转命令 | **TIM6 中断内** |
| 5 ms | 编码器更新、路线规划、位置级联、速度 PI、PWM、命令执行 | **TIM6 中断内** |
| 5 ms | 循迹采样和转向计划（或 PWM 循迹测试） | **TIM6 中断内** |
| 50 ms | LOOP-TEST 慢状态和遥测快照 | **TIM6 中断内** |
| 50 ms | 遥测格式化与发送 | 主循环（延后） |
| 100 ms | OLED 状态页刷新 | 主循环（延后） |
| 主循环 | 串口命令行解析与响应、OLED 缓冲写入 | 主循环 |

**为什么这样分**：USART1 一个字节只要 86.8 µs，而遥测 `snprintf` 8 个字段要
100–300 µs、OLED 的 I2C 刷屏可能上 ms。把它们放进最高优先级中断会压住串口
接收导致丢字节。而位置环、循迹环和速度环按固定 **5 ms** 周期计算，挪到主循环
产生抖动就会算错，所以必须留在中断里。电机速度反馈使用 10 个 5 ms 增量组成的
50 ms 滑动窗口，兼顾 5 ms 更新率和低速量化。

主循环只有：`deferred_run()`（跑延后任务）+ 串口命令行 + `oled_flush()`。

中断在 `sched_init()` 之前不放行任何任务，避免改到还没初始化的对象。

### 4.2 命令队列

按键产生的启停、模式切换、换档命令写入 8 项环形命令队列，由 5 ms 控制任务
集中执行；队列满时丢弃新命令，不覆盖尚未执行的控制动作。

USART1 命令行**同样没有绕开队列的路径**：`l`/`r`/`t`/`stop`/`quiet`/`log` 都写入
同一个队列，由 5 ms 控制任务统一执行，`show` 只读。

参数默认固化在 `config.h`。仅在停车状态允许通过 `tkp/tkd/tkg`、`plkp/plkd`、
`prkp/prkd` 和速度环命令做台架临时整定，最终值必须写回配置并重新编译烧录。

### 4.3 八路数字循迹

#### 4.3.1 传感器与误差

循迹模块是**八路数字量红外**（`irtrack.c` 用 `HAL_GPIO_ReadPin` 读，没有 ADC），
所以只有开关量信息，没有亚传感器分辨率。

驱动层把八路归一化成：`raw = 0` 表示压黑，`raw = 1` 表示白线；`pattern` 的
bit0–bit7 对应 IR1–IR8，压黑置 1。通道权重按物理间距设定：

```text
-25, -17, -9, -3, +3, +9, +17, +25
```

并算出**稳定分母归一化质心**：

```text
e = weight_sum * (1 + B) / (25 * (black_count + B))
B = 0.5
```

误差限幅后约为 `[-1,+1]`。分母加入 0.5 个通道的偏置，减小压黑通道数变化时
分母跳变造成的转向冲击。单路压黑时归一化误差为：

| 压黑通道 | IR1 | IR2 | IR3 | IR4 | IR5 | IR6 | IR7 | IR8 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `e` | −1.000 | −0.680 | −0.360 | −0.120 | +0.120 | +0.360 | +0.680 | +1.000 |

#### 4.3.2 线路有效性

有效线路 = **压黑 1–7 路且连成一段**。另外两种图案判为无效：

- 八路全黑（`TRACK_LINE_VALID_MAX_BLACK = 7U`）
- 断续图案（例如 IR1 和 IR8 都黑、中间全白）——数字量传感器很容易出这种图案
  （斜穿横线、岔路口），不判无效的话质心会算出个"居中"的假象

#### 4.3.3 控制链：位置串速度

```text
归一化红外误差 e + yaw rate
    └─> 转向 PD - 陀螺仪阻尼 ──> 差速比例 u，限幅 ±0.65
          ├─> 内轮 = base * (1 - |u|)
          └─> 外轮 = base * (1 + 0.2*|u|)

左右期望轮速 ──> 左右轮位置参考 ──> 位置 PD ──> 速度 PI ──> PWM
```

TRACK 和 EIGHT 的闭环运动阶段共享这条链路。普通 TRACK 只允许前进；EIGHT 原地
转向和位置测试允许一轮正转、一轮反转。

| 环 | 形式 | 默认参数 |
| --- | --- | --- |
| 转向环 | 归一化 **PD + 陀螺仪阻尼** | `Kp=0.80`、`Kd=0.02`、`Kgyro=0.001`、比例限幅 ±0.65 |
| 连续位置环 | 左右独立 **PD** | 左/右 `Kp=0.35`、`Kd=0.37` |
| 速度环 | 左右独立增量 **PI** | `Kp=0.45`、`Ki=0.12`、`Kd=0`、输出 ±100% |

基础速度以 `120 RPM/s` 斜坡生成。位置参考每 5 ms 按期望轮速积分，位置 PD 输出
再由速度 PI 执行；位置误差使用 ±180° 环绕，支持长时间运行。D 项使用约 20 ms
低通，速度环不使用微分。

**速度环的核心作用不只是调速，而是抗电池掉压**：电池从 12V 掉到 10V，同样的
PWM 转速会掉约 15%，只有闭环才能让"G3 = 100 RPM"始终成立。

普通 TRACK 的有效线和丢线阶段都保持最后转向比例。有效线时 IMU 未就绪或过期会
退化为纯红外；丢线时 IMU 无效立即停车。累计相对航向达到 ±180° 仍无有效线也停车。

#### 4.3.4 计圈

不用控制状态机，直接数 **`e` 偏到一侧**的事件：

- **弯道**：转弯时黑线偏到一侧，`|e|` 很大；
- **起点横线**：压满八路时是对称的，权重和 `-25-17-9-3+3+9+17+25 = 0`，
  所以 **`e ≈ 0`**。

判据是 `|e| >= 0.42` 连续约 20 ms，计一个弯；计完后 200 ms 内不再接受新弯。
累计 4 个弯计一圈。计圈只用于诊断，不改变速度目标，也不自动停车。

计圈确认只影响诊断数据。实车若发现横线误计，增加确认时间；若弯道漏计，减小
阈值。任何计圈参数都不参与速度或转向控制。

> **适用面**：这套计圈假设赛道是「四个直角弯 + 一条起点横线」的矩形。
> 换成 S 弯或连续弯需要重新设计。

#### 4.3.5 状态机

只有三个运行状态：

| 状态 | 进入条件 | 行为 |
| --- | --- | --- |
| `FOLLOW` | 启动或线路有效 | 更新归一化转向；`e` 偏到一侧累计计圈 |
| `LOST` | 线路无效 | **保持丢线前的转向比例**，继续累计搜索位置 |
| `STOPPED` | 停车 | — |

有效线恢复时立即回到 FOLLOW，不做多帧资格确认。丢线后相对航向达到 ±180° 停车；
丢线期间 IMU 失效也立即停车。有效线时 IMU 失效只关闭陀螺仪阻尼，红外仍可循迹。

### 4.4 开环测试模式

| 模式 | 行为 |
| --- | --- |
| PWM 速度测试 | 左右轮同向同速按当前档位跑，默认每 5 秒换一次转向 |
| PWM 循迹测试 | 固定基础占空比加减差速；误差来自注入的**八路图案**，不读真实红外 |

PWM 循迹测试复用归一化误差和转向 PD，但明确旁路位置环与速度环。

**PWM 循迹测试的模拟输入是原始传感器图案，不是一个抽象的角度。** 固件把 8 位图案
直接写进驱动层的 `ir_data.raw[]`，当成八路传感器的读数，再走与实车**逐字相同**的
计算链：驱动层算稳定分母归一化误差（公式见 §4.3.1）→ 循迹模块判线路合法性 →
同一转向 PD 算差速。

图案表共 12 项（`testmode.c` 的 `patternTable[]`），按 IR1→IR8 从左到右写，
`1` = 压黑：

| 图案 | 场景 | `e` |
| --- | --- | --- |
| `11000000` | 左侧大偏移（2 路压黑） | −1.00 |
| `01100000`、`00110000` | 左侧中/小偏移 | −0.62 / −0.29 |
| `00011000` | 居中（IR4+IR5） | 0.00 |
| `00001100`、`00000110` | 右侧小/中偏移 | +0.29 / +0.62 |
| `00000011` | 右侧大偏移 | +1.00 |
| `11110000`、`00001111` | 转弯口（4 路连续压黑） | −0.72 / +0.72 |
| `11111111` | 全黑 = **丢线** | 无效 |
| `00000000` | 全白 = **到终点线** | 无效 |
| `10000001` | 岔路口（中间断开） | 无效 |

`11111111` 压满 8 路，超过 `TRACK_LINE_VALID_MAX_BLACK` 后按横线处理；
`10000001` 中间有白洞，被 `line_is_contiguous()` 挡下。PWM-TRACK 的无效图案只保持
上一测试差速，不调用真实 TRACK 的 180° 丢线停车逻辑。

按键：KEY2 按表中顺序轮换图案，KEY4 短按/长按调基础占空比。每 5 秒
（`PWM_TRACK_TEST_PHASE_MS`）会把**当前图案左右镜像**一次，所以停在任一非对称图案
上就能看到左右自动对调；镜像不改 KEY2 选中的那一项，表本身对镜像封闭。开机默认是
居中的 `00011000`，它是自对称的，所以开机状态下看不到自动镜像的效果。

OLED 的 PWM-TRK 页：

```text
[PWM-TRK]  RUN   第 1 行：8×16 大字号，模式名 + RUN/STOP
PAT 00011000     第 3 行：当前注入的图案（IR1→IR8，1 = 压黑）
PH LEFT  BASE  50%  第 4 行：镜像相位 + 基础占空比
E +0.00 S +0.0   第 5 行：归一化误差 + 测试差速
V 3.61/3.61 Y+012   第 7 行：命令电压 L/R + 航向角
K2 PAT K3 GO K4 BASE 第 8 行：本页按键提示
```

第二行的 `PH:` 就是上面说的那个镜像相位：`LEFT` 表示注入的是 KEY2 选中的原图案，
`RIGHT` 表示注入的是它的左右镜像。

> **OLED 一行能放多少字符**：小字是 6×8 点阵，`128 / 6` = **21 个**；驱动的
> `oled_show_string_small()` 到 `col + 5 >= 128` 就停止写入，**超出的部分被静默丢弃**。
> 别把 `OLED_TEXT_BUFFER_SIZE = 24` 当成显示上限——那只是 `snprintf` 的缓冲区大小
> （23 字符 + 结尾符），两者不是一回事。本页最长的一行 `P:00000000 PH:RIGHT` 是 20 个字符。

**PWM 速度测试的转向控制权。** 默认 5 秒自动来回换向；也可以用串口 `l`/`r`/`t`
手动指定单轮转速（见 §7）。发这类命令会调用 `testmode_set_auto_phase(0)` 关掉
自动换向，`stop` 或切换模式时经 `speed_loop_ResetModeState()` 自动恢复。台架
测单轮正反转就用 `l 30` / `l -30`。

## 6. 通信

USART1 使用 PA9/PA10、115200 bps、8N1：

- TX 走环形缓冲区，`HAL_UART_Transmit_IT` 完成后自动接力。
- RX 用单字节中断接收，中断里只缓存字节转交命令行模块，不解析。
- `HAL_UART_RxCpltCallback` / `HAL_UART_TxCpltCallback` 定义在 `serial.c`。

USART2 的 CubeMX 初始化保留在 `usart.c`，但**应用未使用**（早期版本的蓝牙
手动控制链路已删除）。

## 7. 串口命令

命令通过 USART1 输入，以回车或换行结束。PID 参数固化值在 `config.h`；停车时可用
串口做临时台架整定，最终仍需写回配置并重新编译烧录。

| 命令 | 作用 |
| --- | --- |
| `l <rpm>` | 左轮目标转速，负值反转 |
| `r <rpm>` | 右轮目标转速，负值反转 |
| `t <rpm>` | 左右轮同时设为该值 |
| `stop` | 立即停车（并恢复自动换向） |
| `show` | 打印模式、目标、实际速度、PWM、循迹/位置/速度增益和 IMU 状态 |
| `quiet`、`log` | 暂停 / 恢复 VOFA 输出 |
| `mode <0..4>`、`gear <1..6>` | 切换模式或停车设置档位 |
| `trackdiag` | 50 Hz 循迹调试 CSV，记录误差、陀螺仪、位置参考和左右控制量 |
| `imudiag`、`imucal` | IMU 原始诊断 / 停车重新零偏校准 |
| `tkp/tkd/tkg` | 停车设置共享转向 PD 和陀螺仪阻尼 |
| `plkp/plkd/prkp/prkd` | 分别设置左右连续位置环 Kp/Kd |
| `slkp/slki/slkd`、`srkp/srki/srkd` | 分别设置左右速度环 PI |
| `help` 或 `?` | 显示命令列表 |

`l`/`r`/`t` **只在 PWM-SPEED 模式下生效**（用 KEY1 切过去）。其它模式下轮速目标
另有来源（循迹环、测试相位），改了下一个周期就被覆盖，所以命令行会直接回复
`[MANUAL] only in PWM-SPEED mode`，而不是入队后静默失效。

参数是**严格解析**的：整串必须就是一个数，范围是 ±190（`SPEED_TARGET_LIMIT_RPM`）。
所以 `l abc`、`l 30x`、`l 500`、`l nan` 都会被拒绝并给出提示，**不会入队、也不会把车
置成运行态**；成功时才回显 `[MANUAL] l 30.0 rpm`，队列满时回 `[MANUAL] queue full, dropped`。
（早先没有这道校验：`l abc` 会被 `strtof` 解析成 0 一路送进队列，顺带把车置成运行态。）

这三条命令**走命令队列**：主循环解析、5 ms 控制任务执行，避免和速度环抢状态。
执行时还会关掉 PWM-SPEED 的 5 秒自动换向，把转向控制权交给命令；`stop` 或切换
模式时经 `speed_loop_ResetModeState()` 自动恢复。

命令名不认识回复 `? '<名字>' (type 'help')`，缺参数回复 `? <名字> needs a value`。

`show` 的 `Tgt` 打的是**夹取后**的目标（取自速度环里存的值），所以 `t 500` 不会出现——
它已经在解析处被范围校验挡掉了；而如果下游有别的地方给出超限目标，`show` 显示的也是
车实际执行的那个值。

## 8. VOFA+ 遥测

控制任务更新快照，主循环每 50 ms 发送固定的 8 个逗号分隔字段：

```text
tgtRpmL,rpmFL,tgtRpmR,rpmFR,steerRpm,diffRpm,yawDeg,turnPhase
```

| 字段 | 单位 | 含义 |
| --- | --- | --- |
| `tgtRpmL` / `tgtRpmR` | RPM | 左右轮目标速度 |
| `rpmFL` / `rpmFR` | RPM | 50 ms 滑动计数窗速度 |
| `steerRpm` | RPM | 循迹差速量 |
| `diffRpm` | RPM | 左右实际速度差 |
| `yawDeg` | 度 | IMU963RA 航向角 |
| `turnPhase` | 枚举 | TRACK/EIGHT 当前阶段 |

LR 原始 5 ms 速度和 PWM 使用 `trackdiag` 观察。生产遥测表头由
`telemetry_boot_header()` 统一发出，不在别处硬编码。

## 9. 构建与调试

### 9.1 Keil MDK

用 Keil MDK-ARM 打开 `MDK-ARM/bluecar.uvprojx`，目标 `bluecar`，器件
`STM32F103ZE`。命令行构建：

```powershell
UV4.exe -r MDK-ARM\bluecar.uvprojx -j0 -o build.log
```

### 9.2 VSCode + EIDE

用 VSCode 的 EIDE 插件打开 `MDK-ARM/` 目录（读 `.eide/eide.yml`），
使用同样的 ARMCC 5.06 工具链。

**增删或改名任何源文件时，`bluecar.uvprojx` 和 `.eide/eide.yml` 两个文件都要
同步修改**，包括 `IncludePath` 列表。

### 9.3 主机侧仿真

```powershell
python tools\simulate_tracking.py     # 八路循迹算法
python tools\simulate_control_loops.py # 位置串速度控制链
python tools\simulate_pwm_tests.py    # PWM 测试模式算术
```

脚本直接解析 `Core/system/config.h`，改宏后重跑即可验证，
不需要重新编译固件。**因此该文件里的宏必须是单行的 `#define 名字 数值`**。

### 9.4 串口调试

1. 将 USART1 的 PA9/PA10 接到 USB 串口工具，115200 bps、8N1。
2. 复位后先收到一帧全零数字表头，随后是 8 列 FireWater 数据。
3. 使用 `help` 查看命令，使用 `show` 查看实时闭环状态。

### 9.5 实车调参

允许停车时通过串口临时整定，最终参数必须写回 `config.h`。左右轮和
“速度内环先于位置外环”的顺序不能颠倒：

1. 架空车轮，在 PWM-SPEED 模式分别整定左、右速度 PI。覆盖 ±30/±80/±140 RPM。
2. 用 LOOP-TEST POS-CL 分别整定左、右定点位置 PD。
3. 在地面低速 TRACK 中分别微调 `plkp/plkd` 和 `prkp/prkd`，观察 `trackdiag` 的
   位置误差 P95、速度误差和转向变化率。
4. 最后调共享 `tkp`，再加 `tkg` 陀螺仪阻尼，最后才尝试很小的 `tkd`。
5. 任何出现持续振荡、高频换向或位置误差随时间扩大的参数都放弃。

当前定点台架结果：左轮位置 `Kp=0.12/Kd=0.20`，右轮 `Kp=0.08/Kd=0.20`，
进入/释放死区 `0.8/2.0°`，爬行 `1.5 RPM`。连续轨迹位置环仍保持左右
`Kp=0.35/Kd=0.37`，需要用地面 TRACK 数据继续确认。

## 10. 已知未实现项

- 普通 TRACK 没有独立的赛道终点识别；计圈不自动停车，由用户或上层流程决定停车。
- 普通 TRACK 没有全局堵转判定；堵转检测只用于 LOOP-TEST 台架测试。
- 磁力计只做后台诊断，不参与航向、速度或位置控制。
